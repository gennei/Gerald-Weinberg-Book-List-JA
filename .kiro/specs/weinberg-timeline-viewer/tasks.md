# Implementation Plan

## Tasks

- [x] 1. プロジェクト基盤の構築
- [x] 1.1 (P) ディレクトリ構造とHTMLスケルトンの作成
  - GitHub Pages対応のディレクトリ構造を作成する
  - 基本的なHTMLファイルを作成し、CSS/JSファイルへのリンクを設定する
  - 文字コードとビューポートのメタタグを設定する
  - _Requirements: 3.1, 3.2_

- [x] 1.2 (P) 書籍データJSONファイルの作成
  - 設計で定義されたスキーマに従ってJSONファイルを作成する
  - Gistから取得した18冊の基本データを入力する
  - 追加収集が必要なフィールドは仮データまたはnullで設定する
  - _Requirements: 1.2, 1.5_

- [x] 2. データ読み込み機能の実装
- [x] 2.1 JSONデータの読み込みと状態管理
  - fetch APIを使用して外部JSONファイルを読み込む
  - 読み込み中・完了・エラーの状態を管理する
  - エラー発生時にユーザーへメッセージを表示する
  - _Requirements: 1.2, 3.1_

- [x] 3. テーブル表示機能の実装
- [x] 3.1 テーブルヘッダーの生成
  - 12列のヘッダーを動的に生成する
  - ソート可能な4列（日本語タイトル、原著タイトル、日本語版出版年、原著出版年）にクリックイベントを設定する
  - ソート可能列であることを視覚的に示すスタイルを適用する
  - _Requirements: 1.1, 1.2, 2.1, 2.2, 2.3, 2.4_

- [x] 3.2 テーブルボディの生成
  - 書籍データを行として動的に生成する
  - 各セルに適切なデータを表示する
  - リンク列（Amazon、著者サイト）は`<a>`タグで表示する
  - データが存在しない場合は「—」を表示する
  - ヨミガナはDOMに出力しない
  - _Requirements: 1.1, 1.2, 1.4, 1.5_

- [x] 3.3 初期表示時のソート適用
  - ページ読み込み時に日本語版出版年の昇順でソートする
  - ソート後のデータでテーブルを描画する
  - _Requirements: 1.3_

- [x] 4. ソート機能の実装
- [x] 4.1 ソートロジックの実装
  - 4列それぞれに対応するソート処理を実装する
  - 日本語タイトルソート時はヨミガナをキーとして使用する
  - 文字列の比較にはlocaleCompareを使用する
  - null値は末尾にソートする
  - _Requirements: 2.1, 2.2, 2.3, 2.4_

- [x] 4.2 ソート状態の管理と切り替え
  - 現在のソート列と順序を状態として保持する
  - 同じ列のヘッダーをクリックした場合は昇順/降順を切り替える
  - 異なる列をクリックした場合は昇順でソートする
  - ソート状態をUIに反映する（インジケーター表示）
  - _Requirements: 2.5_

- [x] 5. スタイルの適用
- [x] 5.1 テーブルの基本スタイル設定
  - シンプルで読みやすいテーブルスタイルを適用する
  - ヘッダーとボディの視覚的な区別を付ける
  - 行の境界線と適切なパディングを設定する
  - _Requirements: 1.1, 3.1_

- [x] 5.2 ソート可能列のインタラクションスタイル
  - ソート可能列のヘッダーにホバー効果を追加する
  - 現在のソート列と順序を視覚的に示す
  - クリック可能であることを示すカーソルスタイルを設定する
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5_

- [x] 6. 統合と動作確認
- [x] 6.1 全機能の統合テスト
  - ページ読み込み時にデータが正しく表示されることを確認する
  - 各ソート列が正しく動作することを確認する
  - 欠損データが「—」で表示されることを確認する
  - ローカルサーバーでの動作確認を行う
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 2.1, 2.2, 2.3, 2.4, 2.5, 3.1, 3.2_
